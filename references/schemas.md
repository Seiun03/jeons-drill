# concepts.json 작성 기준

## 형식

```json
{
  "subject": "자료구조",
  "language": "c",
  "concepts": [
    {
      "id": "L03-04",
      "lecture": "3",
      "title": "AVL 트리의 균형 인수",
      "type": "definition",
      "source": "03_트리 p.14-15",
      "key_points": [
        "균형 인수 = 왼쪽 서브트리 높이 - 오른쪽 서브트리 높이",
        "AVL 트리는 모든 노드의 균형 인수가 -1, 0, 1 중 하나",
        "삽입/삭제 후 |균형 인수| = 2가 되면 회전으로 복구"
      ],
      "misconceptions": [
        "노드 수 차이로 착각",
        "루트에서만 균형을 검사한다고 착각"
      ],
      "related": ["L03-05", "L03-06"],
      "weight": 1
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| id | O | `L<강의번호 2자리>-<순번 2자리>`. 한 번 정하면 바꾸지 않는다 |
| lecture | O | 강의 번호 문자열 ("3"). 파일명 앞 번호를 따른다. 번호가 없으면 파일 순서 |
| title | O | 개념 이름 (짧게) |
| type | O | `definition` / `principle` / `formula` / `code` 중 하나 |
| source | O | 노트 파일명(확장자 없이) + 페이지/슬라이드. 예 `03_트리 p.14-15`, `05_정렬 slide 7` |
| key_points | O | 서술형 채점 기준이 되는 핵심 포인트 2~5개. **자료의 표현을 최대한 살려서** |
| misconceptions | | 객관식 오답 선지 재료. 자료에 "주의" 표시가 있거나 흔히 헷갈리는 것 |
| related | | 비교·복합 문제에 쓸 관련 개념 id |
| weight | | 기본 1. exam_info.md에서 강조된 개념은 2 |
| language | | (code 유형) 이 개념만 언어가 다르면 지정. 기본은 최상위 `language` |
| avoid_variants | | 이 개념에 맞지 않는 문제 변형 목록. 예: 순서가 의미 없는 개념이면 `["order"]`. 스크립트가 이 변형을 빼고 고른다 |

## 개념을 나누는 기준

- **문제 하나로 물을 수 있는 크기**가 개념 하나. "트리"는 너무 크고, "AVL 균형 인수", "LL 회전"이 적당하다.
- 강의 하나에 보통 10~40개. 슬라이드 수 / 2 정도가 대략적인 상한.
- 같은 내용이 여러 슬라이드에 반복되면 하나로 합치고 source에 범위를 적는다.
- 목차, 인사, 과제 공지, 참고문헌 같은 슬라이드는 개념으로 만들지 않는다.
- 예제 풀이 슬라이드는 독립 개념이 아니라, 그 예제가 다루는 개념의 source에 포함한다(수학 변형 문제의 재료가 된다).

## type 고르는 기준

| type | 이럴 때 | 예 |
|---|---|---|
| definition | 용어의 뜻·분류·특징을 아는지가 핵심 | 정규화의 정의, 세포 소기관 종류 |
| principle | 왜/어떻게 일어나는지, 과정·순서·인과가 핵심 | TCP 3-way handshake, 광합성 과정 |
| formula | 공식을 쓰거나 계산·증명하는 것이 핵심 | 베이즈 정리, 행렬식 계산 |
| code | 코드를 읽고 쓰고 분석하는 것이 핵심 | 퀵정렬 구현, 포인터 연산 결과 |

하나의 주제가 두 성격을 다 가지면 개념을 둘로 나눈다(예: "퀵정렬 원리"는 principle, "퀵정렬 구현"은 code).

## 중요도(weight) 매기는 기준

`weight: 2`(핵심, ★)는 좆됐어 모드의 우선순위와 `--core`의 기준이다. 다음 순서로 판단한다.

1. `exam_info.md`에서 교수님이 강조했다고 적힌 것, 족보에 나온 것 → 무조건 2
2. 자료 속 명시적 신호: "중요", "시험", "꼭", "★", 굵게·빨간 글씨로 강조, 발표자 노트에서 시험 언급
3. 여러 강의에서 반복해서 나오는 개념, 정리/요약 슬라이드에 다시 나오는 개념
4. 다른 개념의 전제가 되는 기초 개념 (이걸 모르면 뒤 강의가 안 풀리는 것)

신호가 전혀 없으면 강의당 핵심 개념 비율이 대략 1/4~1/3이 되도록 3·4번 기준으로 고른다. 전부 2로 하면 의미가 없다.
