# I'm fucked. 나는 좆됐어. 모드

벼락치기용. 목표는 "남은 시간 안에 시험에 나올 것을 최대한 많이 숙련까지". 말은 짧게, 대기 시간은 최소로.

## 1. 진입

1. `PROG mode cram` 후 한 줄로 알린다: `I'm fucked. 나는 좆됐어. 모드 ON`
2. 시험 시각을 한 번만 묻는다: "시험 언제야? (예: 10-22 09:00) 알려주면 남은 시간으로 계획 세워 줄게. 모르면 건너뛰어도 돼."
   - 답하면 `PROG mode --until "<시각>"`
3. `.drill/concepts.json`이 없으면 → 아래 **가벼운 setup** 후 계속.
4. `PROG stats`의 시간 계획을 보여 준다. 전체 소화율이 80% 미만이면 "핵심만 할까?"를 묻고, 그렇다고 하면 이후 모든 pick과 summary에 `--core`.
5. **요약 단계**로.

## 2. 가벼운 setup

SKILL.md의 Setup을 따르되:
- 그림 검토는 **텍스트가 거의 없는 페이지**(노트 본문이 "(텍스트 없음)"이거나 한두 줄)만 한다. 나머지 IMAGE_REVIEW 표시는 건너뛴다.
- 개념은 굵게: 강의당 **8~20개**.
- weight는 반드시 매긴다 (`schemas.md`의 중요도 신호). 핵심 개념이 하나도 없으면 `--core`가 의미 없어진다.
- 보고는 세 줄로: 강의별 개념 수, 핵심 개수, 건너뛴 그림 수.

## 3. 요약 단계

`PROG summary`로 강의 순서를 확인하고, 강의 하나씩:

1. `PROG summary --lecture N [--core]` → 그 강의의 개념별 핵심 포인트 뼈대
2. 각 개념의 `source` 노트 부분을 읽고, 뼈대 위에 **설명을 덧붙인 요약**을 쓴다:
   - 개념마다 2~4줄. 정의·핵심 공식·대표 예 하나. ★ 표시 유지.
   - "헷갈림 주의"는 그대로 살린다.
   - 자료에 없는 보충은 `(자료 밖 보충)`.
3. 한 답변에 **한 강의**. 개념이 25개를 넘거나 길어지면 두 답변으로 나눈다.
4. 같은 내용을 `.drill/summary.md`에 이어 붙인다. 그 강의 요약이 이미 파일에 있으면 새로 쓰지 말고 파일 내용을 보여 준다.
5. 끝에: `다음 강의 / 요약 그만하고 문제 / 질문`

사용자가 "요약 건너뛰기", "바로 문제"라고 하면 언제든 4로 넘어간다.

## 4. 묶음 드릴 (진단 라운드 포함)

```
PROG pick [--core] [--lecture N]
```
(출제 방식이 '묶어서'면 5개 묶음이 나온다. 사용자가 '한 문제씩'으로 바꿨으면 한 문제씩 나오고, 그때는 SKILL.md의 한 문제 흐름을 따른다.)

- 처음 보는 개념이 남아 있는 동안 스크립트가 **진단 라운드**로 객관식만 준다(`diagnostic: true`, notices에 남은 개수). 따로 할 일은 없고 그대로 출제하면 된다.
- 출력: `batch`(객관식·단답 최대 5개) + `then`(서술형 0~2개).

### 진행 순서
1. `batch` 전부를 한 메시지에 낸다. 형식은 `question-types.md`의 "묶음 형식".
2. 사용자가 한 번에 답한다. 빠진 번호는 `wrong`(패스)으로 본다.
3. 각 문제를 채점하고 **문제마다** `PROG record <id> <result> --asked <level> --note "..."`.
   - 객관식: 확실 정답 `correct`, 애매 정답 `unsure`, 찍음 정답 `guess`, 오답 `wrong`
4. 결과표 한 번 → 틀린 것·애매·찍음만 해설(각 3~4줄, 출처 포함) → 승급·강등 한 줄 → "질문 있으면 해, 없으면 '다음'"
5. `then`이 있으면 서술형을 **한 문제씩** 일반 규칙대로 출제·채점·기록. `injected: true`인 문제는 맞히면 바로 숙련이라는 걸 채점 후에 알려 준다(문제에는 표시하지 않는다).
6. 다시 1번.

### 시간 확인
- 묶음 10번마다 `PROG stats`의 시간 계획 줄만 한두 줄로 보여 준다.
- notices에 마지막 점검 제안이 뜨면 바로 묻는다: "시험까지 X시간. 마지막 점검 할래? 숙련된 거 전부 단답으로 한 바퀴 돌려서 까먹은 거 잡아낼게."

## 5. 마지막 점검

사용자가 하겠다고 하거나 "마지막 점검"이라고 하면:

1. `PROG final`
2. `PROG pick --final`를 `final_done: true`가 나올 때까지 반복. 모든 문제가 `variant: final_check`.
   - 각 개념을 **짧은 단답식**으로 묻는다. `recent_questions`와 다른 각도로.
   - record의 `--asked`는 `mastered`.
   - 틀리거나 애매하면 서술형으로 강등된다. 결과표에 강등을 표시한다.
3. 끝나면: 점검한 개수, 강등된 개념 목록. 남은 시간이 있으면 `PROG pick --weak`으로 강등된 것부터 다시.

## 6. 나가기

"일반 모드"라고 하면 `PROG mode normal`. 진도는 그대로 유지된다.
